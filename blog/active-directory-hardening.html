Active Directory Hardening Checklist

By Khurshed Alam · Cybersecurity Engineering Notes

Active Directory is still the backbone of identity for most enterprise networks — and it's also the single most attractive target once an attacker gets a foothold. Almost every ransomware incident I've read a post-mortem on shares one pattern: initial access on a low-privilege machine, followed by AD misconfiguration abuse to reach Domain Admin. Hardening AD isn't about buying a product — it's about closing paths that are usually already there by default.

This is the checklist I use when auditing a lab (or real) AD environment, roughly in order of impact.

1. Audit privilege paths, don't just count admins

Counting Domain Admins is not enough — nested group memberships, ACL misconfigurations, and delegated permissions create hidden paths to the same privilege. Tools like BloodHound map these paths visually and consistently surface issues like:

  • Service accounts with GenericAll or WriteDACL rights on high-value objects
  • Users with unconstrained delegation enabled on their machines
  • Stale group nesting that grants privilege no one remembers approving

2. Kill Kerberoasting exposure

Any service account with a Service Principal Name (SPN) is Kerberoastable — an attacker can request a ticket and crack the password offline. Mitigate by:

  • Using long, randomly generated passwords (25+ characters) for service accounts, ideally via Group Managed Service Accounts (gMSA)
  • Auditing and removing unnecessary SPNs
  • Monitoring for abnormal TGS-REQ volume, a common Kerberoasting signal

3. Disable NTLM where you can, monitor it where you can't

NTLM relay attacks remain effective because NTLM is still enabled by default in most environments. Practical steps:

  • Enable SMB signing domain-wide
  • Enforce LDAP signing and channel binding
  • Where NTLM can't be fully removed, monitor authentication logs for relay-pattern anomalies

4. Tier your admin model

The single biggest structural fix: stop using Domain Admin accounts to log into workstations or Tier-1 servers. A tiered administration model (Tier 0 = domain controllers and identity systems, Tier 1 = servers, Tier 2 = workstations) with dedicated admin accounts per tier breaks the most common lateral-movement chain outright.

5. Harden default settings

  • Set a strong, enforced password and lockout policy — and consider a fine-grained policy for service/admin accounts
  • Disable the default Print Spooler service on domain controllers (closes a known abuse path)
  • Regularly review and clean stale computer and user objects — they're unmonitored attack surface
  • Enable Advanced Audit Policy logging so the events above are actually visible in your SIEM
Lab it before you trust it. I run this checklist against a self-built lab AD forest, use BloodHound to confirm each fix actually removes the attack path (not just the symptom), and document before/after — this is the basis of the Active Directory Security Lab case study in my Projects section.

Priority order if you only have time for three

  1. Audit privilege paths with BloodHound and fix what it finds — this catches issues no checklist alone will.
  2. Move to a tiered admin model — this breaks the most common attack chain structurally.
  3. Enforce SMB/LDAP signing and reduce NTLM exposure — this closes the most common initial relay vector.
