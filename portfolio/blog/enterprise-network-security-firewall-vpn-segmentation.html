Enterprise Network Security: Firewalls, VPNs & Segmentation

Mohammad Khurshed Alam· Published July 2026· 7 min read· Intermediate
Firewall DesignVPNVLAN SegmentationCCNP

A flat network is a gift to an attacker: one compromised workstation can reach the file server, the domain controller, and the finance VLAN in the same hop. Good enterprise network security design starts with the assumption that something inside the perimeter will eventually be compromised — and limits what it can reach when it is.

01Introduction

Firewalls, VPNs, and VLANs are the three pillars of the traditional network security stack, and they're still relevant even in a cloud-first world — most enterprises still run hybrid environments with on-prem servers, site-to-site links, and remote access VPNs that need the same rigor as any cloud control plane.

02Common Design Weaknesses

  • Flat networks: user, server, and management traffic sharing the same broadcast domain.
  • Overly permissive firewall rules: "any-any" rules left over from a troubleshooting session and never removed.
  • Split-tunnel VPN misconfiguration: remote users routing both corporate and internet traffic without inspection.
  • No east-west inspection: firewalls guarding the perimeter but nothing filtering traffic between internal VLANs.
  • Shared local admin credentials across endpoints, turning one compromised machine into lateral movement everywhere.

03Best Practices

  • Segment by function and trust level: separate VLANs for users, servers, management/OOB, guest Wi-Fi, and IoT/printers — with routing between them controlled by firewall policy, not just a router ACL.
  • Apply least-privilege firewall rules: explicit source/destination/port rules, default-deny, and a documented change-review process — no standing "any-any."
  • Harden VPN access: require MFA on the VPN gateway, use split-tunnel only for trusted destinations, and prefer modern protocols (IKEv2/WireGuard) over legacy PPTP/L2TP.
  • Deploy an internal firewall or ACLs between VLANs so a compromised endpoint in one segment can't freely scan or pivot into another.
  • Use 802.1X port-based authentication on switch ports so unknown devices can't just plug in and reach the network.
Field note: the single highest-impact change on most networks I've assessed is separating the management VLAN (switches, firewalls, hypervisors) from the user VLAN — it's a low-effort change that removes an entire class of lateral-movement paths.

04Enterprise Recommendations

  • Review firewall rule bases at least semi-annually and remove unused or overly broad rules.
  • Log and monitor VPN authentication events alongside on-prem AD sign-ins for correlated anomaly detection.
  • Maintain an up-to-date network diagram — you can't segment or defend what isn't documented.
  • Run periodic internal vulnerability scans (not just external) to catch misconfigurations between segments.

05Conclusion

Perimeter security alone hasn't been sufficient for years. Segmentation, least-privilege firewall policy, and hardened remote access work together to make sure a single compromised device is a contained incident — not a company-wide breach.
